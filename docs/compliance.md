# 고객 응대 고지 문안 (고객사 약관·처리방침)

이 문서는 고객사가 약관과 개인정보 처리방침에 넣을 **고지 문안의 템플릿**과, 이메일 안에서 AI 응대를 어디에 어떻게 밝히는지를 적는다. 문안의 법적 효력과 적법성은 고객사의 법무 담당자나 자문 변호사가 정한다.

> **법률 자문 아님.** 이 문서는 기술 문서다. 아래 문안은 시작점이며, 법률 판단을 대신하지 않는다. 보존 기간, 국외 이전 근거, 동의 방식, 고지 시점은 고객사가 확정한다.

## 1. 고지가 필요한 지점

| 지점 | 무슨 일이 생기나 | 고지할 내용 |
|---|---|---|
| 이메일 응대 | 문의 본문이 AI 상담 에이전트로 분류되고, 답장 초안이 작성된다. 일부는 자동 발송된다 | AI 응대 사실, 자동 발송과 담당자 검토의 구분, 사람에게 넘기는 기준 |
| 외부 언어모델 호출 | 문의 본문(연락처 등은 가린 뒤)이 LLM 제공자 API 로 전송된다 | 제공자 범주, 전송 항목, 국외 이전 여부 |
| 매뉴얼 변환 | 관리자가 올린 매뉴얼 본문이 LLM 제공자 API 로 전송된다 | 전송 사실과 올리지 말아야 할 문서(개인정보, 내부 전용 문서) |
| 원문 보존 | 종결 뒤 일정 기간이 지나면 원문과 주소가 제자리에서 가명화된다 | 보존 기간(`RETENTION_DAYS`), 파기 방식 |
| 정보주체 요청 | 열람과 삭제 요청을 처리한다 | 요청 방법, 처리 기한, 처리자 기록 |

비이메일 매체(채팅, 문자 등)의 내용은 이 문서 범위 밖이다.

## 2. 이메일 안의 AI 표시 위치

응답 메일은 서버가 템플릿으로 만든다(`server/mail/index.js`의 `renderAgent`). 표시 문구는 코드에 고정돼 있고 팩이나 콘솔로 끌 수 없다. 자리는 두 곳이다.

**인사 바로 아래 (소개 줄)**

- 한국어: `안녕하세요, {고객 이름} 님.` 다음 줄에 `{회사명}의 AI 상담 에이전트 {에이전트 이름}입니다.`
- 영어: `Hello {name},` 다음 줄에 `This is {agent name}, the AI support agent at {company}.`

**맺음 줄 (발송 방식)**

| 발송 방식 | 한국어 | 영어 |
|---|---|---|
| 자동 발송(L2 intent) | 이 메일은 AI 상담 에이전트가 자동으로 보냈습니다. | This email was sent automatically by our AI support agent. |
| 담당자 검토 후 발송 | 이 메일은 담당자 검토 후 발송되었습니다. | This email was sent after review by our staff. |

고객사가 바꿀 수 있는 것은 `COMPANY_NAME`(회사명)과 `AGENT_NAME`(에이전트 이름)뿐이다. 에이전트 이름에 사람 이름을 쓰면 고지가 흐려지므로 AI 임을 드러내는 이름을 쓴다. 사람이 쓴 답장(담당자 직접 답장)은 `renderHuman` 템플릿을 쓰며 AI 표시가 없다. 그 답장은 사람이 쓴 것이다.

## 3. 약관 고지 문안 템플릿

아래 문안의 `{…}` 자리를 고객사 정보로 채운다. 확인이 필요한 항목은 `[확인]` 으로 표시했다.

> **제 ○ 조 (AI 상담 응대)**
>
> ① {회사명}(이하 "회사")은 고객 문의 응대의 일부를 인공지능(AI) 상담 에이전트가 처리하도록 운영할 수 있습니다.
>
> ② AI 상담 에이전트가 작성한 답변은 회사가 정한 안내 범위 안에서 만들어지며, 일부는 담당자의 검토를 거쳐 발송되고 일부는 자동으로 발송됩니다. 자동으로 발송된 메일에는 그 사실을 표시합니다.
>
> ③ AI 상담 에이전트가 판단하기 어렵거나 환불, 계약, 법적 문제, 개인정보 관련 요청 등 사람의 판단이 필요한 문의는 담당자에게 넘겨집니다.
>
> ④ 회사는 문의 응대를 위해 문의 내용을 {LLM 제공자 범주, 예: 외부 언어모델 API 사업자} 에 전송할 수 있습니다. 전송할 때 연락처 등 개인정보는 가려서 보냅니다. [확인: 국외 이전 여부와 이전 국가, 위탁 계약 근거]

**처리방침용 항목 (같은 내용을 개인정보 처리방침에 옮길 때)**

| 항목 | 채울 내용 | 비고 |
|---|---|---|
| 처리 목적 | 고객 문의 응대, 응답 품질 관리 | [확인] 목적 범위 |
| 처리 항목 | 메일 주소, 이름, 메일 제목과 본문, 응대 기록 | 폼 메일은 입력 칸에서 가져온 주소를 포함할 수 있다 |
| 보존 기간 | 종결 뒤 {RETENTION_DAYS}일 후 원문과 주소를 가명화. 응대 기록(상태, 분류)은 집계를 위해 남는다 | [확인] 보존 기간은 법무 결정. 설정하지 않으면 자동 가명화를 하지 않는다 |
| 처리 위탁·국외 이전 | 메일 발송 사업자, LLM 제공자 API | [확인] 위탁 계약과 국외 이전 근거 |
| 정보주체 권리 | 열람과 삭제를 요청할 수 있다. 회사는 요청을 처리하고 처리자를 기록한다 | 요청 접수 창구와 기한을 적는다 |
| 접속기록 | 관리 화면의 조회·수정과 감사 내보내기 기록을 보관한다 | [확인] 보관 기간 |

## 4. 배포 전 확인 목록

- [ ] 실제 발송 메일 샘플에서 소개 줄과 맺음 줄이 위 표와 같다(한국어와 영어 각각). `COMPANY_NAME`·`AGENT_NAME` 값이 고객사 이름과 맞다.
- [ ] 약관 조항과 처리방침 항목의 `[확인]` 이 모두 법무 확인을 거쳤다.
- [ ] 매뉴얼 변환 화면의 고지 문구("올린 매뉴얼 본문은 변환을 위해 LLM 제공자 API로 전송됩니다")가 약관 내용과 맞다.
- [ ] `RETENTION_DAYS` 값이 처리방침의 보존 기간과 같다. 켜기 전에 치명 평가 건을 내보낸다(`docs/deployment.md` §7).
- [ ] 감사 내보내기 manifest 의 `templates.email` 해시를 이번 배포의 기록으로 남긴다. 나중에 같은 템플릿이었는지 비교할 수 있다.
- [ ] 감사 내보내기 파일과 manifest 는 소유자만 읽고 쓰는 권한(0600)으로 만들어진다. 다른 곳으로 옮기거나 넘길 때도 접근 권한을 좁게 유지한다.
- [ ] 정보주체 요청 처리 절차(`scripts/subject-request.js`)를 운영 담당자가 알고 있다.

## 5. 바꾸는 방법

- 소개 줄과 맺음 줄의 문구는 코드(`server/mail/index.js`)에 있다. 문구를 바꾸면 코드 리뷰를 거치고, 감사 내보내기의 `templates.email` 해시가 달라진다.
- 회사명과 에이전트 이름은 환경 변수로 바꾼다(`COMPANY_NAME`, `AGENT_NAME`).
- 약관 문안과 처리방침은 이 저장소 밖의 고객사 문서다. 이 문서는 템플릿으로만 쓴다.
